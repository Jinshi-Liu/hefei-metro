# 合肥轨道交通网络数据来源与处理说明

## 1. 数据范围

本项目以合肥轨道交通1—8号线为基础研究网络，以2026年11月12日正在开展试乘活动的S1线（合肥段）作为独立扩展情景。

现有数据包括：

- 1—8号线：215条线路—车站记录，195个不同站名。
- S1试乘线路：10个开放试乘站点。
- 1—8号线：19座由跨线路同名识别的候选换乘站。
- 候选换乘边：21条。
- 相邻车站区间记录：216条（含S1的9条）。

上述统计由本项目Python程序从CSV数据计算得到，不直接等同于官方运营统计。

## 3. 数据处理方法

使用Python的csv模块完成数据读取，通过NetworkX建立无向网络模型。

主要处理步骤：

1. 根据线路站点顺序生成相邻车站运行边。
2. 在物理车站网络中合并基础线路中的同名车站。
3. 在站点—线路网络中分别建立各线路层的车站节点。
4. 根据同名车站生成候选换乘边，并记录核验状态。
5. 将S1作为独立试乘线路，暂不加入未经核实的站内换乘连接。
6. 使用GraphML保存网络，CSV保存数据与统计结果。

## 4. 时间数据可用性

已经建立216条区间记录组成的运行时间数据表，以及21条候选换乘边核验记录。

截至本阶段，尚未获得覆盖全部区间、能够可靠复核的运行时间和换乘分钟数。

因此，当前采用无权网络建模。后续可以使用站数和换乘次数建立明确的代理出行代价，并进行参数敏感性分析。

不得将代理代价直接解释为真实出行分钟数。

## 5. 当前数据局限

- 部分运营状态与换乘方式尚未逐项获得现行官方确认。
- 2023年历史换乘公告不能代替2026年运营公告。
- 同名节点合并或候选换乘边连接不等于实际可直接换乘。
- 无完整客流、列车容量、班次和运行耗时数据。
- 网络图为拓扑示意图，不反映真实地理距离。

因此，本阶段成果属于可复现的初步网络模型，后续实验必须明确候选换乘边的使用假设。

## 6. 数据与代码管理

整理后的线路与换乘表位于 `data/processed/`，历史准备代码位于 `src/preparation/`，GraphML 网络位于 `results/networks/`。`data/raw/` 的原始资料登记仍需补齐。

后续核验修改应同步记录来源、日期和处理规则，以保证实验结果能够复现。
