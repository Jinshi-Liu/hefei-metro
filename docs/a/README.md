# 合肥轨道交通复杂网络分析项目

## 一、项目简介

本项目为《复杂系统分析》课程期末大作业。

研究主题：合肥轨道交通关键换乘节点识别与出行鲁棒性分析。

核心研究问题：网络结构中心性较高的换乘站，是否也是换乘中断后造成较大出行损失的站点？

项目采用Python和NetworkX构建两种网络，为后续节点重要性分析、换乘中断模拟和出行路径评价提供基础。

## 二、研究范围

主实验：合肥轨道交通1—8号线。

扩展情景：S1线试乘区段。

当前数据统计：

| 项目 | 1—8号线 | 加入S1试乘线路 |
|---|---:|---:|
| 物理网络节点数 | 195 | 205 |
| 多层网络节点数 | 215 | 225 |
| 线路区间记录数 | 207 | 216 |
| 候选换乘边数 | 21 | 21 |

S1作为独立试乘情景建模，暂未加入与3号线合肥西站之间的站内换乘边。

## 五、两种网络模型

### 1. 物理车站网络

节点：物理车站。

边：相邻车站之间的线路连接。

同名候选换乘站在主网络中合并为单个节点。

用途：车站结构重要性分析，包括度中心性、介数中心性等。

### 2. 站点—线路多层网络

节点：车站与所属线路组成的节点，例如：

`合肥南站_L1`

`合肥南站_L4`

边分为两类：

- `running`：同一线路内的运行边。
- `candidate_transfer`：尚待完成现行通道核验的候选换乘边。

候选换乘边具有：

`traversable="false"`

**重要：NetworkX不会自动根据这个属性禁止通行。**

如果后续进行最短路径或可达性分析，必须显式过滤未经核实的边，或者在明确说明假设后建立单独的实验情景网络。

## 七、给B同学的使用说明

B同学负责中心性分析、路径评价和单站换乘中断实验。

建议：

1. 基础中心性分析使用1—8号线物理车站网络。
2. 换乘中断模拟使用站点—线路多层网络，并排除S1试乘节点。
3. 当前21条候选换乘边尚未全部获得2026年现行通道确认，不应直接视为已核实的可通行连接。
4. 模拟换乘中断时，应删除目标换乘站对应的换乘边，保留运行边及线路层车站节点。
5. 路径评价采用物理站点起终点，不要将同一物理车站的多个线路副本当成不同出行需求。
6. 缺少真实分钟数据时，使用明确的站数与换乘次数代价模型，不得将其描述为实际出行时间。

## 八、数据局限

当前网络是可复现的初步结构模型。

部分站点运营状态、换乘通道及时间参数仍需要进一步核实。

没有可靠证据支持的运行分钟数和换乘分钟数均保持空值。

所有网络统计和后续分析都需要说明所使用的模型版本、边筛选规则及相关假设。

## 十、可复现性说明

当前代码支持从CSV数据重新构建网络、计算结构指标并保存图表。`src/preparation/` 是历史脚本集合，不应按编号盲目全部运行：部分准备脚本会覆盖 `data/processed/` 中现有输入或核验数据。运行任何脚本前应检查其读写路径、依赖及输出，先备份数据与结果。

后续修改线路和换乘数据时，先确认输入和备份，再有选择地运行相关建网、统计及可视化程序；它们也会覆盖对应结果。

为保证结果可追溯，建议在正式实验前固定数据版本并备份原始输入文件。
